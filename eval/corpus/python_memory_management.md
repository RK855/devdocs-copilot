# Python 内存管理

## 引用计数与垃圾回收

CPython 用引用计数管理内存，对象引用归零立即释放。循环引用无法靠引用计数解决，由分代垃圾回收器定期处理。

`gc.collect()` 可以手动触发回收，通常不需要，但在长生命周期进程中处理大量循环引用对象时有用。

## 常见内存泄漏

- 全局缓存无限增长
- 事件监听器注册后未注销
- 闭包持有大对象
- 线程或任务未结束
- 循环引用配合 `__del__`

Python 的泄漏多是“逻辑泄漏”：对象仍被引用，垃圾回收器无能为力。用 `tracemalloc` 或对象计数定位增长来源。

## 弱引用

`weakref` 允许引用对象而不阻止回收，适合缓存与监听器。`WeakValueDictionary` 在值被回收后自动删除条目，是缓存的好工具。

## 大对象

大列表、字典、DataFrame 占用大量内存。分块处理、生成器、流式读取能降低峰值。不要把整个文件读进内存再解析。

## 生成器

生成器惰性求值，适合处理大数据流。但生成器只能遍历一次，需要多次遍历时要重新创建或转列表（会增加内存）。

## 对象开销

Python 对象本身有额外开销，小对象数量巨大时内存惊人。`__slots__`、dataclass slots、数组模块能减少开销。数值密集场景用 NumPy 而不是列表。

## 监控

生产环境关注 RSS 增长趋势。短时间波动正常，持续单调上升说明泄漏。容器内存限制要留余量，避免 OOM 被杀。

## 常见坑

- 全局字典缓存不设上限
- 忘记取消订阅或定时任务
- 在循环里累积结果列表
- 读取超大文件不分块
- 用 `del` 以为能立即释放，实际仍有引用
