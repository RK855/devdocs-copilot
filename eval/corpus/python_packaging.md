# Python 项目打包与依赖管理

## 依赖声明

`requirements.txt` 列出直接依赖并锁定版本，保证不同环境装到同一套包。`pip freeze` 生成的全量快照包含间接依赖，适合完全复现环境，但不适合手工维护。

区分两类文件：`requirements.txt` 写直接依赖（可读、可升级），`requirements-lock.txt` 写全量快照（可复现）。两者都提交，但只在直接依赖变化时重新生成快照。

## 虚拟环境

每个项目一个虚拟环境，避免全局包冲突。`python -m venv venv` 创建，激活脚本在 `venv/Scripts/activate`（Windows）或 `venv/bin/activate`（类 Unix）。

CI 与脚本中不必激活，直接调用 `venv/Scripts/python.exe` 更可靠，避免 shell 差异导致的环境错乱。

## 版本约束

`==` 精确锁定，`>=` 与 `<` 组合表达范围，`~=` 兼容版本。生产环境建议精确锁定，避免上游小版本变更引入行为差异。升级要有测试兜底。

## 依赖瘦身

只声明真正直接 import 的包。间接依赖由 pip 解析，不需要重复声明。体积大但只在开发时用的包（pytest、ruff）应分开到开发依赖，不打进生产包。

判断一个依赖是否必须显式声明：代码里是否直接 import。若直接 import 但只靠间接依赖带入，版本变化时可能突然缺失，属于隐性依赖。

## 打包分发

标准库 `zipapp` 可以打单文件 zip；`wheel` 是库分发的标准格式；应用打包用 PyInstaller、Nuitka 等工具生成可执行文件。

PyInstaller onedir 模式生成目录，启动快、便于排查；onefile 生成单文件，启动时解压到临时目录，稍慢。打包要显式收集数据文件（静态资源、模板、预置语料），否则运行时找不到。

打包产物的路径要与开发环境区分：可执行文件所在目录用于存放可写数据（配置、数据库、上传文件），包内资源目录只读。冻结状态下用 `sys.frozen` 判断，资源根用 `sys._MEIPASS`。

## 排除无用模块

PyInstaller 会把被 import 的模块及其依赖打包，体积容易膨胀。通过 `excludes` 排除未使用的重型库（GUI、绘图、科学计算），通过 `hiddenimports` 补充动态导入的模块。每次打包后检查体积变化，防止无意引入大包。

## 版本号与发布

语义化版本：主版本表示不兼容变更，次版本表示新增功能，修订号表示修复。发布时打标签，CI 构建产物并附到 Release。

## 常见坑

- 依赖不锁版本，换机器装出不同行为
- 忘记把新 import 的包写进 requirements
- 打包时漏掉数据文件
- 把 .env 与数据目录打进分发包
- 在系统 Python 里直接装包
- 虚拟环境提交进仓库
