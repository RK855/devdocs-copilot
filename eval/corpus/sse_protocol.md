# SSE 服务端推送

## SSE 是什么

Server-Sent Events 是基于 HTTP 的单向服务器推送协议。客户端发起一个普通 GET/POST 请求，服务端保持连接，持续发送文本事件。相比 WebSocket，SSE 更简单、天然支持断线重连、可穿过多数代理，但只能服务端到客户端单向通信。

## 响应格式

响应头必须是：

```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

响应体由若干事件块组成，每块以空行结束：

```
event: delta
data: {"text": "你好"}

event: done
data: {}

```

字段包括 `event`（事件名）、`data`（数据，可多行）、`id`（事件 id，用于断线续传）、`retry`（重连间隔毫秒）。注释行以冒号开头，可用于心跳。

## 事件设计

常见事件：`meta`（元信息，如会话 id、模式）、`sources`（引用来源）、`delta`（增量文本）、`phase`（阶段进度）、`done`（结束）、`error`（错误）。

结束事件应携带完整结果或至少状态，让前端能收尾。错误事件要带机器可读 code，前端按 code 分支展示，不要依赖文案匹配。

## 心跳与代理超时

长时间无数据时，中间代理可能断开连接。定期发送注释行 `: ping` 保活，间隔通常 15 到 30 秒。没有心跳的 SSE 在 Nginx 默认 60 秒超时后会被切断。

Nginx 还需要关闭缓冲：`proxy_buffering off;`，否则事件会被攒起来一次性发出，失去流式效果。`X-Accel-Buffering: no` 响应头也能达到类似效果。

## 客户端解析

浏览器原生 `EventSource` 只支持 GET，且不能自定义请求头。需要 POST 或携带 Authorization 时，用 `fetch` + `ReadableStream` 手动解析。

解析难点：事件帧以空行分隔，网络分片可能在任意位置切断，不能假设一次 read 就能拿到完整帧。要按 `\r\n` 或 `\n` 归一化，缓冲区累积后按 `\n\n` 切分。收到 `[DONE]` 之类的结束标记后主动关闭读取。

## 断线重连

原生 EventSource 会自动重连，服务端可用 `id` 与 `Last-Event-ID` 做续传。手动 fetch 实现则需要自己做重试与去重。重试前要避免重复请求带来的副作用，写操作应幂等。

## 取消与资源释放

客户端关闭连接后，服务端生成器应收到取消信号。FastAPI 的流式响应在客户端断开时会取消异步生成器，但阻塞线程里的上游调用不会自动停止。需要在 `finally` 中关闭上游连接，并取消后台任务，否则上游仍在计费或占用连接。

## 何时不用 SSE

需要双向实时通信、二进制流、低延迟游戏场景应选 WebSocket。只需要一次性下载大文件则用普通流式响应，不需要事件格式。

## 常见坑

- 忘记设置 `text/event-stream`
- 没有心跳被代理超时
- 事件之间没有空行导致前端解析失败
- 断连后后台任务未取消，资源泄漏
- 错误在流开始后返回 500（状态码已发送，不可能）
