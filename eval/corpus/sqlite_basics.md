# SQLite 基础使用

## 特点与适用场景

SQLite 是嵌入式关系数据库，整个库是单个文件，不需要独立服务进程。适合本地工具、桌面应用、测试环境和小流量站点。写入是串行的：同一时刻只允许一个写事务，高并发写入场景不适合。它支持标准 SQL 的大部分语法，事务遵循 ACID。

连接用 `sqlite3.connect("app.db")`，用完要 `close()`，或用 `with` 上下文管理器自动提交并释放。默认每次写操作都会隐式开事务，批量插入要显式 `BEGIN` 再统一 `COMMIT`，否则每条语句一次磁盘同步，速度极慢。

## 参数化查询与索引

拼字符串构造 SQL 会带来注入风险，正确做法是参数化：`cursor.execute("SELECT * FROM user WHERE name = ?", (name,))`。占位符用 `?` 或命名形式 `:name`，驱动会负责转义。

索引能加速等值查询与范围查询，但会增加写入开销与存储。给 `WHERE`、`JOIN`、`ORDER BY` 常用的列建索引；组合索引遵循最左前缀原则。用 `EXPLAIN QUERY PLAN` 查看是否走了索引，出现 `SCAN TABLE` 说明全表扫描。

## 常见坑

- 用字符串拼接 SQL，导致注入
- 多线程共享同一个连接，SQLite 连接默认不跨线程使用
- 忘记提交事务，数据只存在于连接中
- 大批量写入逐条提交，性能极差
- 在 SQLite 里期待高并发写，遇到 `database is locked`
