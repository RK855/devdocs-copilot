# Redis 缓存基础

## 数据结构

Redis 是内存键值数据库，支持字符串、哈希、列表、集合、有序集合、位图、HyperLogLog。选对结构能让操作从 O(n) 降到 O(1)。

- String：缓存对象、计数器
- Hash：对象的字段级读写
- List：队列、时间线
- Set：去重、交集并集
- ZSet：排行榜、延迟队列

## 过期与淘汰

`EXPIRE` 设置过期时间，`TTL` 查询剩余时间。过期策略有惰性删除与定期扫描，内存紧张时按策略淘汰。`maxmemory-policy` 常用 `allkeys-lru` 或 `volatile-lru`。

缓存键必须设置过期时间，否则内存只增不减。

## 原子操作

`INCR` 原子自增，适合计数与限流。`SETNX` 实现分布式锁的雏形，但要注意过期时间与误删问题。复杂原子逻辑用 Lua 脚本，保证在服务端一次性执行。

## 分布式锁

`SET key value NX PX 30000` 加锁，value 用唯一标识，释放时用 Lua 校验值再删除，避免删掉别人持有的锁。锁要设置过期时间防止死锁，但过期时间过短会导致业务未完成锁已释放。

## 缓存一致性

先更新数据库再删除缓存是常见策略，配合延迟双删减少不一致窗口。强一致场景不要用缓存，或者使用写穿透加版本号校验。

## 持久化

RDB 定时快照，AOF 追加日志。RDB 恢复快但可能丢数据，AOF 更完整但文件更大。生产常用混合持久化。缓存场景可以关闭持久化，允许丢失。

## 连接与性能

用连接池复用连接，避免每次新建。批量操作用 pipeline 减少往返。避免大 key 与大范围扫描，`KEYS` 在生产禁用，用 `SCAN` 渐进遍历。

## 监控

关注内存使用、命中率、慢查询、连接数、淘汰次数。命中率低说明缓存策略有问题，可能键设计不合理或 TTL 太短。

## 常见坑

- 不设过期时间导致内存打满
- 用 KEYS 阻塞主线程
- 大 key 导致网络与内存抖动
- 锁没有唯一值，误删他人锁
- 缓存与数据库更新顺序错误
