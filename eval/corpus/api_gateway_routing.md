# API 网关基础

## 网关的职责

API 网关位于客户端与服务之间，统一处理路由、鉴权、限流、日志、协议转换、灰度。它让后端服务专注业务，把横切能力集中在一处。

## 路由

按路径前缀或域名转发到不同服务。路由规则要避免歧义，长前缀优先匹配。上游服务地址变化时只改网关配置。

## 鉴权

网关可以统一校验 token，把用户身份通过请求头传给后端。后端仍需做权限判断，不能只依赖网关。内部请求头要防止客户端伪造，需由网关覆盖而非透传。

## 限流

按 IP、用户、API key 维度限流。令牌桶允许突发，漏桶平滑流量。限流阈值要结合容量测试结果设置，过严会误伤正常用户。

## 超时与重试

网关设置上游超时，避免请求无限挂起。重试只对幂等请求且限制次数。网关重试会放大后端压力，需谨慎。

## 日志与追踪

网关是记录访问日志的最佳位置，包含请求 id、耗时、状态码、上游服务。生成 trace id 并透传给后端，形成完整链路。

## 协议转换

外部 REST 与内部 gRPC 之间转换是常见需求。网关负责序列化差异，后端不需要同时支持两套协议。

## 灰度与流量切分

按比例把流量分到新旧版本，观察错误率与延迟再决定是否全量。灰度要能快速回滚。

## 常见坑

- 网关成为单点故障
- 透传客户端伪造的身份头
- 限流按全局而非维度
- 重试风暴放大故障
- 日志缺失导致无法排查
