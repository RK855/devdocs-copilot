# OpenAPI 契约

## 作用

OpenAPI 用 JSON/YAML 描述 HTTP 接口：路径、方法、参数、请求体、响应、错误。它是前后端与文档的共同契约，也能生成客户端代码与测试。

## 自动生成

FastAPI 根据路由与 Pydantic 模型自动生成 `/openapi.json`，并提供 `/docs` 交互文档。模型声明的类型与约束会体现在 schema 中。

## 响应模型

路径操作要声明 `response_model`，否则文档只能给出笼统的 200 响应，前端无法得知字段结构。不同状态码可以用 `responses` 声明多套模型，例如 404、422。

## 示例与描述

`Field(description=...)`、`example` 让文档更可读。接口级 `summary` 与 `description` 说明业务背景。缺少描述的接口文档形同虚设。

## 契约一致性

文档与实现不一致会让前端踩坑。契约测试可以在 CI 中对比实际响应与 schema，发现字段缺失或类型变化。变更契约要同步通知调用方。

## 版本与兼容

新增可选字段兼容；删除字段、改类型、改语义不兼容。破坏性变更升版本或提供过渡期双字段。

## 客户端生成

根据 OpenAPI 生成 TypeScript 客户端能减少手写类型错误。生成代码要随契约更新，并纳入版本管理。

## 安全声明

在 schema 中声明认证方式（Bearer、OAuth2、API key），文档页面才能提供正确的调试入口。

## 常见坑

- 不声明响应模型，文档无字段信息
- 实际返回与 schema 不一致
- 错误响应没有建模
- 接口描述缺失
- 契约变更不通知调用方
