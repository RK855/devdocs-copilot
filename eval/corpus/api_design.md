# HTTP 接口设计规范

设计 HTTP 接口时，方法语义要和操作匹配：GET 只用于读取数据，必须安全且幂等，
不能在 GET 里修改服务器状态；POST 用于创建资源，服务器收到请求体后新建一条记录，
通常返回 201 Created；PUT 用于整体替换且幂等；DELETE 用于删除。

请求体统一用 JSON 格式，客户端在 header 里设置
`Content-Type: application/json`。字段命名保持一致，必填字段缺失或类型错误时，
服务端应返回 400 或 422，并在响应体里说明哪个字段出了问题；
找不到资源返回 404，服务端内部错误返回 500，不要把异常堆栈直接暴露给客户端。

## 分页与版本

返回列表数据的 GET 接口必须支持分页，常见做法是查询参数 `?page=1&size=20`，
响应里带上 total 总数。接口版本可以放在 URL 前缀里（如 /v1/orders），
也可以放在 header 里。好的接口设计不依赖具体框架，
无论用什么语言和库，方法语义、状态码和 JSON 请求体的约定都是通用的。
