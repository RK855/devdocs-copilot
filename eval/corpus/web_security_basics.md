# Web 安全基础

## SQL 注入

把用户输入直接拼进 SQL 会导致注入。`SELECT * FROM users WHERE name = '` + input + `'` 在输入为 `' OR 1=1 --` 时绕过校验。防御方式是参数化查询或 ORM，绝不字符串拼接。输入校验只能作为辅助，不能作为主要防线。

## XSS 跨站脚本

把用户输入直接渲染到 HTML 会执行脚本，窃取 Cookie 或冒充操作。防御：

- 输出转义，按上下文选择 HTML、属性、JS、URL 转义
- 富文本用白名单清洗
- 设置 `Content-Security-Policy` 限制脚本来源
- Cookie 加 HttpOnly，降低被窃取的影响

前端用 `innerHTML` 拼接用户内容风险最高，优先用 `textContent`。必须渲染 Markdown 时要先做 sanitize。

## CSRF 跨站请求伪造

攻击者诱导已登录用户访问恶意页面，借浏览器自动带 Cookie 的特性发起请求。防御用 SameSite Cookie、CSRF token、校验 Origin/Referer。纯 JWT 放在 Authorization 头时天然免疫，因为浏览器不会自动带上。

## 路径穿越

上传或下载文件时，文件名含 `../` 可能读写到预期目录之外。防御：只取 basename、白名单扩展名、规范化路径后校验前缀、用服务端生成的 id 命名文件而非用户文件名。

## 文件上传

限制大小与类型，校验真实内容而非只看扩展名。存储目录不要可执行，文件名不要直接来自用户。解析文档时注意解压炸弹与超大 PDF。上传文件应与代码目录隔离。

## 认证与授权

认证确认身份，授权确认权限。每个受保护接口都要校验，不能只在前端隐藏按钮。越权（IDOR）是常见漏洞：把 URL 里的 id 换成别人的就能访问。服务端必须校验资源归属。

## 密钥管理

密钥放环境变量或密钥管理服务，不进仓库、不进镜像、不打日志。`.env` 加入 `.gitignore`，示例文件只放占位符。泄露后立即轮换，历史提交里的密钥也算泄露。

## 依赖安全

第三方包可能有已知漏洞。定期审计依赖，锁定版本，关注安全公告。不要引入来源不明的包，供应链攻击可能直接执行恶意代码。

## 限流与防刷

登录、短信、AI 调用等接口要限流，按 IP、用户、设备多维限制。防止暴力破解与资源滥用。返回 429 并带 Retry-After，避免攻击者无限重试。

## 常见坑

- 只在前端校验参数
- 把密钥写进前端代码
- 错误信息泄露堆栈与内部路径
- 上传目录与静态资源目录重叠
- 用用户输入直接拼命令（命令注入）
