# RAG 检索增强生成基础

## 为什么需要 RAG

大模型的知识有截止时间，且容易编造细节。RAG 在生成前先检索相关文档，把证据放进上下文，让回答基于外部资料。它同时解决知识更新与可追溯两个问题：文档可替换，答案可标注来源。

## 离线索引流程

1. 文档解析：PDF、Word、Markdown 转纯文本
2. 切分：按语义边界切成带重叠的 chunk
3. 向量化：用 embedding 模型把 chunk 转成向量
4. 入库：向量与元数据写入向量库，同时建关键词索引

切分粒度是关键参数。块太大，检索命中后上下文冗余、噪声多；块太小，语义不完整、指代丢失。常用 300 到 800 字符，重叠 10% 左右。

## 在线检索流程

1. 查询改写（可选）：补全指代、扩展同义词
2. 召回：向量检索 + 关键词检索
3. 融合：RRF 或加权合并
4. 精排：cross-encoder 对候选重新打分
5. 证据判定：分数低于阈值则拒答
6. 生成：把 top-k 证据拼进 prompt，要求基于证据回答

## 混合检索

向量检索擅长语义相似，关键词检索擅长精确匹配（专有名词、代码标识符、错误码）。两者互补。RRF（Reciprocal Rank Fusion）用排名而非分数融合，公式为对每个结果累加 `1/(k+rank)`，k 常取 60。它不需要归一化不同系统的分数，鲁棒性好。

## 精排

粗排召回 20 条后，用 cross-encoder 把 query 与每个候选拼接打分，精度更高但更慢，所以只对少量候选使用。精排分数可用于设置证据门：最高分过低说明没有真正相关的内容，应该拒答而不是硬答。

## 证据门与拒答

RAG 最大的风险是“检索不到却照样编”。证据门在生成前判断是否存在可靠证据：

- 语义证据：余弦相似度或精排分数超过阈值
- 关键词证据：BM25 命中核心词

任一成立即可作答，都不成立则返回固定拒答文案，不调用生成模型。这样能显著降低幻觉率，代价是可能误拒一些本可回答的问题。

## 上下文组织

把证据编号后拼进 prompt，要求模型引用编号。控制总长度，避免超过上下文窗口。去重相邻重复块，保留多样来源。顺序上把最相关的放前面，部分模型对开头更敏感。

## 评测指标

- Recall@k：前 k 条是否命中标注的相关块
- MRR：首个相关块排名的倒数均值
- Precision@k：前 k 条中相关块的比例
- 拒答准确率：无答案题被正确拒绝的比例

评测集要有标注的相关块，且语料规模要足够大，否则 top-k 召回率会虚高。

## 常见坑

- 切分破坏语义，块内没有完整信息
- 只用向量检索，漏掉精确关键词
- 检索结果不判相关性直接喂给模型
- prompt 没要求基于证据回答
- 评测集太小，指标虚高
- 文档更新后没有重建索引
